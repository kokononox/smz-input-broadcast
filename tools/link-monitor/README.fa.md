# ابزار Windows برای پایش و آزمون لینک Pico

این ابزار Windows پورت USB CDC پیکوی مادر را باز می‌کند، گزارش سریال را نشان می‌دهد و دو حالت دستی دارد: آزمون فریم ساختگی و `capture-only`. در capture-only، پس از تأیید آشکار کاربر، رویدادهای کلید و ماوس این Windows به Pico کلاینت فرستاده می‌شوند؛ محتوای ورودی روی دیسک ذخیره یا در گزارش‌ها نمایش داده نمی‌شود. فریمور کلاینت فقط فریم را اعتبارسنجی و ACK می‌کند و هیچ HIDای اجرا نمی‌کند.

## پیش‌نیاز و ساخت در Windows 11

1. .NET 8 SDK را نصب کنید.
2. در PowerShell به این پوشه بروید.
3. اجرا کنید:

```powershell
dotnet publish .\SmzLinkMonitor.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

فایل اجرایی در مسیر `bin\Release\net8.0-windows\win-x64\publish\SmzLinkMonitor.exe` ساخته می‌شود. اگر هنگام ساخت، بستهٔ `System.IO.Ports` در دسترس نباشد، اتصال اینترنت برای دریافت بسته لازم است.

## پایش آزمون‌های فریمور

1. فریمورهای MASTER و CLIENT مربوط به همان آزمونی را که اجرا می‌کنید روی بردهای درست فلش کنید.
2. سیم UART را با بردهای خاموش ضربدری وصل کنید: GP8 مادر به GP9 کلاینت، GP9 مادر به GP8 کلاینت، و GND به GND.
3. Pico مادر را با USB به Windows وصل کنید؛ برنامه را باز کنید، COM را انتخاب کنید و «اتصال» را بزنید.
4. برنامه روی 115200 baud گزارش USB CDC را می‌خواند. RTT نمایش‌داده‌شده زمان رفت‌وبرگشت است، نه تأخیر یک‌طرفه.

## آزمون ساختگی Windows → Pico → کلاینت

با فریمورهای `HOST_MASTER` و `CLIENT`، پس از اتصال COM دکمهٔ «شروع آزمون ساختگی» را بزنید. برنامه هر ۲۰ میلی‌ثانیه یک فریم ثابت و شمارنده‌دار می‌فرستد؛ با «توقف آزمون» ارسال قطع می‌شود. این حالت ورودی انسانی را نمی‌خواند.

## Capture-only (فقط دریافت و ACK)

این حالت hook سراسری کلید و ماوس Windows را فقط پس از فشردن دکمه و تأیید هشدار نصب می‌کند. رویدادهای فشردن/رهاکردن کلید، حرکت، دکمه و چرخ ماوس به‌صورت فریم از COM مادر به کلاینت می‌روند. صف کوتاه فقط در حافظه است؛ محتوا نه در فایل ذخیره می‌شود و نه در UI/لاگ چاپ می‌شود. برنامه با دکمهٔ توقف یا بستن پنجره hookها را برمی‌دارد. رویدادها به کامپیوتر کلاینت فرستاده می‌شوند، اما فریمور فعلی آن‌ها را اجرا نمی‌کند و HID خاموش است.

فقط روی دستگاه‌هایی که اجازهٔ آزمایششان را داری از این حالت استفاده کن؛ هنگام آزمایش رمز یا ورودی حساس تایپ نکن. روی کلاینت باید `CLIENT,event=...` و `ack=...` برابر باشند و `invalid`, `gaps`, `crc` صفر بمانند. سمت مادر باید شمارنده‌های `tx` و `ack` را نشان دهد و خطاها صفر بمانند. اگر صف محلی پر شود، برنامه فقط تعداد رویدادهای کنارگذاشته‌شده را هنگام توقف گزارش می‌کند؛ محتوای آن‌ها را نگه نمی‌دارد.

CRC فقط برای تشخیص خطای تصادفی است، نه رمزنگاری. این نمونهٔ capture-only اجرای HID ندارد.
