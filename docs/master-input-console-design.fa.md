# طرح برنامهٔ مادر برای پخش ورودی SMZ

## هدف MVP

برنامه‌ای برای Windows 11 که ورودی عادی موس و صفحه‌کلیدِ سیستم مادر را هنگام فعال‌بودن پخش به **یک کلاینت SMZ** بفرستد. کامپیوترهای مادر و کلاینت تحت کنترل کاربر و در یک اتاق هستند. نسخهٔ اول برای سنجش تأخیر و کیفیت است.

## معماری موردنظر

`موس/صفحه‌کلید مادر → برنامهٔ Windows → COM رمزنگاری‌شده → Pico مادر → لینک بردبه‌برد → Pico کلاینت → مسیر فعلی Pico/Pro Micro → کامپیوتر کلاینت`

تقسیم وظایف کلاینت طبق توضیح کاربر: تایپ در Pico انجام می‌شود و حرکت موس در Arduino Pro Micro. مسیر کلیک و اسکرول باید با رفتار فعلی کلاینت تطبیق داده شود. برنامهٔ Windows برای دریافت ورودی عادی، جزء جدید این پروژه است؛ مخزن قبلی `ams-shell` فرمان‌های ماکروی ازپیش‌تعریف‌شده می‌فرستد و `CursorSync` فقط نمونهٔ موقعیت نشانگر را برای همگام‌سازی مبدأ می‌فرستد.

## بررسی پایه‌ها و ناسازگاری پیدا‌شده

- نقشهٔ سیم‌کشی v7 پیوست‌شده در گفتگو، پایه‌های **GP4 (پایهٔ فیزیکی ۶)** و **GP5 (پایهٔ فیزیکی ۷)** را آزاد نشان می‌دهد.
- اما قالب فریمور Pico `0.9.60` در شاخهٔ PR 41، **GP4 را برای دکمهٔ Start/Stop** و GP3 را برای Pause/Resume تنظیم کرده است. بنابراین وضعیت GP4 در نقشه و فریمور با هم سازگار نیست؛ معلوم نیست کدام‌یک مطابق فریمور واقعاً فلش‌شده روی بردهای فعلی است.
- **GP16/GP17 (پایه‌های فیزیکی ۲۱/۲۲)** طبق نقشه و فریمور UART0 موجود برای ارتباط Pico با Pro Micro هستند و به مبدل سطح ولتاژ ۵ ولتی می‌روند؛ این پایه‌ها برای لینک جدید آزاد نیستند.
- در صورت تأیید اینکه فریمور نهایی GP4/GP5 را آزاد می‌گذارد، این دو پایه نامزد UART1 بین دو Pico هستند. تا رفع ناسازگاری بالا، سیم‌کشی یا استفاده از GP4/GP5 تأیید نشده است.
- طول کابل هدف بیش از ۰٫۵ و کمتر از ۳ متر است. پایداری لینک و زمین/ایزولاسیون دو کامپیوتر باید روی سیم‌کشی واقعی آزمایش شود.

## ترتیب شروع

1. تطبیق نسخهٔ سیم‌کشی v7 با فریمور واقعاً فلش‌شده و تعیین پایه‌های آزاد نهایی.
2. ساخت آزمون لینک Pico-to-Pico فقط برای heartbeat/ACK و اندازه‌گیری تأخیر/خطا؛ این مرحله هیچ ورودی HID اجرا نمی‌کند.
3. پس از تأیید لینک، افزودن مسیر دریافت ورودی Windows از COM رمزنگاری‌شده.
4. آزمون یک کلاینت؛ ثبت تأخیر و نوسان و بررسی مسیر موس/کیبورد جداگانه.

## رفتار لازم برای MVP

- شروع/توقف دستی و وضعیت پخش آشکار.
- در قطع لینک یا توقف برنامه، کلاینت ورودی‌های نگه‌داشته‌شده را رها کند و دریافت فرمان تازه را متوقف کند.
- رویداد خام در فایل یا تاریخچه ذخیره نشود.
- پس از موفقیت یک کلاینت، دربارهٔ چندکلاینتی‌شدن تصمیم گرفته شود.

## تصمیم لازم پیش از اتصال

آیا بردهای فعلی با فریمور متکی بر GP4/GP3 کار می‌کنند، یا سیم‌کشی v7 با دکمه‌های GP2/GP3 نصب شده و فریمور متناظر آن هم روی Picoها فلش شده است؟
