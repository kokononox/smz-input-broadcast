# طرح برنامهٔ مادر برای پخش ورودی SMZ

## هدف MVP

برنامه‌ای برای Windows 11 که ورودی عادی موس و صفحه‌کلیدِ سیستم مادر را هنگام فعال‌بودن پخش به **یک کلاینت SMZ** بفرستد. کامپیوترهای مادر و کلاینت تحت کنترل کاربر و در یک اتاق هستند. نسخهٔ اول برای سنجش تأخیر و کیفیت است.

## معماری موردنظر

`موس/صفحه‌کلید مادر → برنامهٔ Windows → COM رمزنگاری‌شده → Pico مادر → لینک بردبه‌برد → Pico کلاینت → مسیر فعلی Pico/Pro Micro → کامپیوتر کلاینت`

تقسیم وظایف کلاینت طبق توضیح کاربر: تایپ در Pico انجام می‌شود و حرکت موس در Arduino Pro Micro. مسیر کلیک و اسکرول باید با رفتار فعلی کلاینت تطبیق داده شود. برنامهٔ Windows برای دریافت ورودی عادی، جزء جدید این پروژه است؛ مخزن قبلی `ams-shell` فرمان‌های ماکروی ازپیش‌تعریف‌شده می‌فرستد و `CursorSync` فقط نمونهٔ موقعیت نشانگر را برای همگام‌سازی مبدأ می‌فرستد.

## تخصیص پایه‌ها و وضعیت فعلی

- کاربر تأیید کرده دکمه‌های فیزیکی روی **GP3 و GP4** به‌همراه GND هستند؛ این پایه‌ها برای لینک جدید استفاده نمی‌شوند.
- **GP16/GP17** در UART0 موجود برای ارتباط Pico با Pro Micro استفاده می‌شوند و مسیرشان از مبدل سطح ولتاژ ۵ ولتی می‌گذرد؛ این پایه‌ها نیز برای لینک جدید آزاد نیستند.
- کاربر تأیید کرده **GP8/GP9 روی هر دو Pico آزادند**. این‌ها پایه‌های UART1 مورد استفاده در آزمون آزمایشی‌اند.
- طول کابل هدف بیش از ۰٫۵ و کمتر از ۳ متر است. پایداری لینک و زمین/ایزولاسیون دو کامپیوتر باید روی سیم‌کشی واقعی آزمایش شود.

نقشهٔ v7 پیوست‌شده در گفتگو GP2/GP3 را برای دکمه‌ها نشان می‌دهد، اما کاربر وضعیت واقعی را GP3/GP4 تأیید کرده است؛ وضعیت واقعی بردها مبناست و نقشهٔ v7 برای این جزئیات نیازمند اصلاح است.

قالب فریمور Pico `0.9.60` در شاخهٔ PR 41 هم GP4 را برای Start/Stop و GP3 را برای Pause/Resume تعریف می‌کند: [قالب فریمور Pico در PR 41](https://github.com/kokononox/smz/blob/dc81e1d8f6202ac28cc3f086f921b5c3e339ef88/firmware/pico-light-0.9.60-template.py).

## ترتیب شروع

1. **آزمون لینک Pico-to-Pico:** heartbeat/ACK و اندازه‌گیری RTT روی GP8/GP9؛ این مرحله هیچ ورودی HID اجرا نمی‌کند.
2. پس از تأیید لینک، افزودن دریافت ورودی Windows از COM رمزنگاری‌شدهٔ موجود.
3. آزمون یک کلاینت؛ ثبت تأخیر و نوسان و بررسی مسیر موس/کیبورد جداگانه.

## رفتار لازم برای MVP

- شروع/توقف دستی و وضعیت پخش آشکار.
- در قطع لینک یا توقف برنامه، کلاینت ورودی‌های نگه‌داشته‌شده را رها کند و دریافت فرمان تازه را متوقف کند.
- رویداد خام در فایل یا تاریخچه ذخیره نشود.
- پس از موفقیت یک کلاینت، دربارهٔ چندکلاینتی‌شدن تصمیم گرفته شود.
