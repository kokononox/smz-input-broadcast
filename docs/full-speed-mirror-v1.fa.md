# نسخهٔ کامل پخش یک‌طرفهٔ SMZ — v1

این شاخه یک مسیر کاملِ آزمایشی برای **یک رایانهٔ مادر و یک کلاینت مجاز** فراهم می‌کند:

`ماوس/صفحه‌کلید Windows → برنامهٔ بومی Raw Input → USB CDC/COM → Pico Master → UART1 GP8/TX → GP9/RX Pico Client → USB HID مقصد`

## اجزا

- `windows/MirrorMaster`: برنامهٔ Windows با دکمه‌های اتصال/شروع/توقف؛ دریافت Raw Input فقط پس از تأیید و زدن Start آغاز می‌شود. توقف با دکمه یا `Ctrl+Shift+F12` است. ورودی خام ثبت یا روی دیسک ذخیره نمی‌شود.
- `firmware/master_bridge`: فریمور Pico مادر؛ فقط فریم‌های مجاز با CRC درست را عبور می‌دهد، ACK یا گزارش رویداد HID برنمی‌گرداند.
- Pico کلاینت باید فریمور گیرندهٔ سازگار داشته باشد که پشتیبانی از رویدادهای `0x02`, `0x03`, `0x04`, `0x05` و `0x07` را پیاده‌سازی می‌کند. گیرندهٔ شاخهٔ native mirror فعلی UART1 را با 1,000,000 baud می‌خواند و در صورت قطع ارتباط، وضعیت را آزاد می‌کند.

## پروفایل سرعت

- UART1 روی 1,000,000 baud و 8N1 است؛ این مقدار برای سازگاری با گیرندهٔ فعلی نگه داشته شده. بالا بردن baud بدون تغییر و آزمون هر دو سر لینک سازگاری را می‌شکند.
- مسیر Master بدون ACK و بدون log رویداد کار می‌کند. برنامهٔ Windows رویدادها را به صف محدود می‌فرستد و نوشتن دسته‌ای COM را در thread جدا انجام می‌دهد؛ حرکت ماوس جدا از snapshot وضعیت کلید/دکمه عبور می‌کند.
- Heartbeat هر 100 ms فرستاده می‌شود. گیرندهٔ فعلی watchdog حدود 350 ms دارد و هنگام توقف/قطع لینک باید ورودی‌های نگه‌داشته‌شده را آزاد کند.
- اعداد فوق تنظیمات طراحی‌اند، نه نتیجهٔ بنچمارک روی سخت‌افزار. تأخیر end-to-end، نرخ افت فریم و پایداری روی کابل واقعی باید اندازه‌گیری شوند.

## سیم‌کشی

- Pico Master GP8/TX → Pico Client GP9/RX
- GND دو Pico → یکدیگر
- سیم RX برگشتی روی Master لازم نیست. 5V را بین بردها وصل نکنید؛ هر برد را با USB خودش تغذیه کنید.
- دکمه‌های فیزیکی GP3 و GP4 روی کلاینت برای روشن/خاموش‌کردن Mirror استفاده می‌شوند و به لینک UART وصل نمی‌شوند.

## ساخت و دریافت خروجی

GitHub Actions گردش‌کار `Build full-speed SMZ mirror` دو artifact می‌سازد: `SMZ-Mirror-Master-Bridge-UF2` و `SMZ-Windows-Mirror-Master`. تا سبزشدن هر دو job، روی برد مقصد HID واقعی را آزمایش نکنید.

## محدودیت‌های اعتبارسنجی

این branch هنوز به‌صورت end-to-end روی دو برد و دو رایانه آزمایش نشده است. build سبز فقط صحت ساخت را تأیید می‌کند، نه تأخیر یا پایداری واقعی. اجرای آزمایشی را با یک کلاینت و یک پنجرهٔ خالی انجام دهید؛ شروع ارسال نیازمند تأیید آشکار است و توقف فوری در برنامه در دسترس است.
