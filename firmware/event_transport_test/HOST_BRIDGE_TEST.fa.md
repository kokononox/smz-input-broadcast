# آزمون Windows → Pico مادر → Pico کلاینت

این مرحله مسیر COM کامپیوتر مادر تا UART کلاینت را با فریم‌های ساختگی می‌سنجد. برنامهٔ Windows فقط با کلیک کاربر روی «شروع آزمون ساختگی» یک الگوی ثابت را با نرخ اسمی ۵۰ فریم‌برثانیه می‌فرستد. این مرحله ورودی واقعی موس/صفحه‌کلید را capture نمی‌کند، چیزی ذخیره نمی‌کند و روی کلاینت HID اجرا نمی‌کند.

## فایل‌های آزمون

از اجرای موفق workflow با نام `Build host bridge test firmware`، artifact `SMZ-Host-Bridge-Test-UF2` را دریافت و از حالت فشرده خارج کنید:

- `host-master/smz_event_transport_test.uf2` را روی Pico مادر فلش کنید.
- `event-client/smz_event_transport_test.uf2` را روی Pico کلاینت فلش کنید.

این UF2ها موقتاً جای فریمور جاری را می‌گیرند؛ قبل از فلش از فریمور اصلی نسخهٔ پشتیبان داشته باشید.

## اجرا

1. اتصال قبلی UART را حفظ کنید: GP8 مادر به GP9 کلاینت، GP9 مادر به GP8 کلاینت، و GND مشترک. ۵ ولت را به GPIO وصل نکنید.
2. Pico مادر را به کامپیوتر مادر و Pico کلاینت را به کامپیوتر کلاینت وصل کنید.
3. نسخهٔ جدید `SMZ-Link-Monitor-win-x64` را اجرا کنید، COM مادر را باز کنید و «شروع آزمون ساختگی» را بزنید.
4. در COM مادر باید `MASTER,mode=host-test` دیده شود؛ در COM کلاینت باید `CLIENT,event=...` دیده شود.

نتیجهٔ موفق: `tx` و `ack` نزدیک به ۵۰ در هر گزارش یک‌ثانیه‌ای؛ `timeout=0`, `busy=0`, `invalid=0`, `crc=0`, `host_crc=0`. در خروجی کلاینت انتظار می‌رود `event` و `ack` برابر و `invalid=0`, `gaps=0`, `crc=0` باشند. RTT مادر از لحظهٔ ارسال Pico مادر تا رسیدن ACK کلاینت را می‌سنجد و زمان انتقال Windows→USB داخل آن نیست.

اگر COM مادر باز است ولی `host_rx=0` می‌ماند، نسخهٔ جدید برنامه و نقش `HOST_MASTER` را بررسی کنید. اگر `host_rx>0` و `tx>0` ولی `ack=0` است، خروجی COM کلاینت را برای تفکیک مشکل دریافت/پاسخ بفرستید.
